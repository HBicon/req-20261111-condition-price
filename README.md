# 成色价展示（按应用渠道虚拟加价）

需求 ID：`REQ-20261111-001`

在手机回收报价详情页中新增“成色价”展示样式，并在后台增加“虚拟加价配置”。后台按应用渠道配置估价金额区间、虚拟加价系数和封顶金额，前台同时展示原估价、虚拟加价和新估价。

## 本次方案调整

- 后台菜单字段：应用渠道、估价金额最低值、估价金额最高值、虚拟加价系数、封顶金额。
- 应用渠道支持父子层级：子渠道优先使用本渠道规则，未命中时逐级继承父渠道规则。
- 前台成色价与预估价均展示新估价；主价格下方拆解原估价、虚拟加价和加价后的新估价。
- 区间价按最高值命中规则，区间首尾同步加价，主价格展示加价后的最高值，并补充完整新估价区间。

## 前台交互

- 默认使用“有得卖 App”渠道，可在价格卡内的“应用渠道”下拉切换；也可通过 `?channel=app-wechat` 等 URL 参数进入指定渠道。
- 默认展示“成色价”，主价格显示当前成色的新估价，五档成色同时展示新估价与原价。
- 主价格下方展示“原估价 + 虚拟加价 = 新估价”，并标注规则来源、命中区间、系数、封顶金额及是否已触顶。
- 子渠道命中父渠道规则时显示“继承 有得卖 App”等来源；子渠道存在同区间专属规则时优先使用子渠道规则。
- 切换至“预估价”后，按同一渠道和同一套规则展示新预估价。
- 底部报价、询高价提示和后台预览均使用同一套计算结果。

演示原估价：靓机 `¥4,923`、小花 `¥4,650`、大花 `¥4,180`、外爆 `¥3,260`、内爆 `¥2,450`。

## 计算口径

```text
虚拟加价 = min[原估价最高值 × (虚拟加价系数 − 1)，封顶金额]
新估价最低值 = 原估价最低值 + 虚拟加价
新估价最高值 = 原估价最高值 + 虚拟加价
```

其中虚拟加价四舍五入取整。单值估价的最低值与最高值相同；区间价按最高值匹配应用渠道规则，并将同一加价金额同步加到区间首尾。

以“有得卖 App”为例：

| 成色 | 原估价 | 命中规则 | 虚拟加价 | 新估价 |
| --- | ---: | --- | ---: | ---: |
| 靓机 | ¥4,923 | 4,000–4,999，系数 1.05，封顶 ¥200 | +¥200 | ¥5,123 |
| 小花 | ¥4,650 | 4,000–4,999，系数 1.05，封顶 ¥200 | +¥200 | ¥4,850 |
| 大花 | ¥4,180 | 4,000–4,999，系数 1.05，封顶 ¥200 | +¥200 | ¥4,380 |
| 外爆 | ¥3,260 | 3,000–3,999，系数 1.03，封顶 ¥100 | +¥98 | ¥3,358 |
| 内爆 | ¥2,450 | 0–2,999，系数 1.02，封顶 ¥60 | +¥49 | ¥2,499 |

切换到“微信小程序”时，4,000–4,999 区间命中其专属规则（系数 1.04、封顶 ¥180）；其他区间继续继承“有得卖 App”规则。

## 后台配置

访问 `/config.html` 进入“虚拟加价配置”菜单。

- 规则字段包含应用渠道、估价金额最低值、估价金额最高值、虚拟加价系数、封顶金额和启停状态。
- 同一渠道内的启用区间不可重叠；不同渠道允许配置相同区间。
- 子渠道规则与父渠道规则同时匹配时，优先使用子渠道规则；子渠道未配置或未命中时，再逐级向上查找。
- 支持新增、编辑、启用停用、删除和恢复默认规则。
- 右侧预览可切换应用渠道，实时查看五档原估价、虚拟加价、规则来源和新估价。
- 配置保存在浏览器 `localStorage`（键名 `virtual-markup-rules-v2`），前后台页面实时同步，仅用于静态原型演示。

默认渠道树：

| 应用渠道 | 父渠道 | 默认规则 |

| 微信小程序 | 有得卖 App | 4,000–4,999：1.04 / ¥180，其余继承 App |

| 抖音小程序 | 有得卖 App | 继承 App |
